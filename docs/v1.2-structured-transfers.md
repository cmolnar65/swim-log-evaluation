# v1.2 recorded conversion and prescription export contract

## Recorded swim conversion

The owner opens **Create structured prescription from this swim**, reviews the read-only preview and confirms creation of a new private prescription. An optional date creates and links a future planned workout. Leaving the date empty creates no schedule. Confirmation rechecks ownership and a hash of the current source evidence. Changed sources require a new preview. Failed scheduling/linking removes only the newly created records.

Conversion currently accepts pool swims with 1–499 ordered lengths, or laps when lengths are absent. Each active row becomes a step. Stroke, distance and units must be reliable, and step distance must reconcile with the recorded total. Unknown stroke, incomplete distance evidence, totals-only and open-water records require manual authoring. No set boundaries or repeat counts are guessed. Explicit rest rows are retained; absent rest stays unspecified. Measured times are descriptive observations, never inferred targets. Private notes, GPS and original source documents are excluded. Recorded swims and personal-best evidence are unchanged.

Repeated explicit confirmations intentionally create independent copies; this is not a deduplicating import. Each copy retains private source-ID provenance and remains editable as a future prescription.

## Export actions

Saved owner-private prescriptions offer FIT, PDF and UTF-8 text downloads. Each attachment requires the current owner's capability and a nonce bound to both prescription ID and format. FORM text can be copied locally with a manual selection fallback; the plugin does not transmit it to FORM. The swimmer must review FORM's interpretation.

PDF uses bundled Dompdf 3.1.6 with remote resources, embedded PHP and JavaScript disabled. Unicode text is escaped before rendering. Runtime Composer dependencies are installed by the normal production staging builder; validation does not create a distribution ZIP.

FIT is a Garmin Workout file (file type 5), sport swimming/lap swimming. Distance, stroke, drill, supported equipment and repeat control records retain prescription semantics. Yards convert to FIT meters without changing the text/PDF unit. Numeric rest means seconds; M:SS is also accepted. Explicit 0 means continuous swimming. Unspecified leaf rest becomes an open lap-button rest, disclosed before download. Group rests occur after the group iteration. An individual `on M:SS`, `@ M:SS` or `send-off M:SS` uses repetition-time timing and cannot also prescribe additional rest. `M:SS/100m` or `M:SS/100yd` encodes a speed target. Other pace prose, excessive FIT strings and unsupported timing fail explicitly; PDF/text remain available without truncation. Multiple/custom equipment remains in notes with a warning. FIT exports permit at most 1,000 encoded steps including rests and repeat controls.

A standard FIT workout is not a TrainingPeaks completed-activity upload. TrainingPeaks currently documents **.zwo-only planned-library imports**. This implementation does not promise that TrainingPeaks accepts planned swimming FIT uploads and does not fabricate activity history to bypass that limitation.

References: [Garmin Workout file specification](https://developer.garmin.com/fit/articles/file-types/workout.html), [TrainingPeaks planned workout imports](https://help.trainingpeaks.com/hc/en-us/articles/32432105650573-Import-Planned-Workouts-into-TrainingPeaks). Independent CI decoding uses Garmin's official Python SDK 21.218.0; it is not shipped in the plugin.

## Acceptance still required

Automated tests use synthetic records only. Actual device acceptance of the FIT workout, FORM interpretation and user-site workflow/layout acceptance remain separate manual checks. No confidential PDFs are included in tests or packages. No database schema change is introduced.
