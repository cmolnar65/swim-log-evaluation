# Calendar pool-length warning repair

The recorded calendar card renderer in includes/class-blocks.php accessed pool_length_m, but Calendar::workout_row in includes/class-calendar.php did not include that field in its normalized response. The synthetic fixture correctly supplied 25 metres for the pool workout and null for the open-water workout. Both lost the key during normalization. This was a production service/renderer contract mismatch, not incomplete fixture data.

The normalized row now always includes pool_length_m as a float when recorded or null when absent/unknown. It does not infer a pool length from native units, rewrite source data or fabricate a value for open water. Privacy exclusions and ownership remain unchanged.

CalendarTest covers metric/native-yard lengths and null/missing source values. The real WordPress calendar-day regression asserts service and rendered-card values and converts PHP warnings during rendering to exceptions, restoring the previous error handler afterward. This catches a recurrence rather than accepting successful assertions alongside warnings.

No schema or release metadata changes. The historical warning remains in prior validation records; new log inspection determines whether it is resolved for this commit.
