## Corrections made

1. The old collection post-type identifier, `swimlog_training_plan`, exceeded WordPress's 20-character limit and prevented imports. New collections use `swimlog_train_plan`. A private compatibility registration/read path for `swimlog_training_pla` preserves any legacy truncated rows. Deduplication includes both valid types. An explicit legacy fixture is readable, remains unchanged, and prevents duplicate import through its fingerprint.
2. Collection metadata writes and the import fingerprint are now verified by reading back the intended values. Failed collection creation removes its new post; failed membership writes restore previous metadata; failed import finalization removes its new structures and collection. Unchanged, already-correct metadata remains valid.
3. Malformed selection/candidate/source-line shapes are rejected, and structured/review units must agree. Scheduling validates exact date syntax before DateTime parsing and uses the site timezone.
4. Duplicate Week now uses an exclusive boundary seven days after its start. The previous six-day boundary omitted the final day.
5. Recorded prescription history now survives clearing a match, changing status, or deleting the planned row. Before those transitions, the existing completed association is captured in private structure metadata. Legacy completed links remain locked and are captured lazily when changed. If that history cannot be persisted, the transition fails before changing the plan. Copies do not inherit the lock metadata.

No SQL table definitions, schema version, stable metadata, release branch, tags or SVN were changed. The private metadata/history handling is idempotent and requires no SQL schema migration or bulk rewriting of existing records. The source PDFs and private extracted content were neither used as fixtures nor committed.
