# Garmin measurements and historical imports — v1.3 test guide

Version 1.3-dev is for testing. Public release remains 1.2 and release is on hold. Database schema is 1.3; historical jobs use private non-autoloaded records in the existing WordPress options table and require no additional schema change.

## Install the test build

Build the installable ZIP with [build-v1.3-test.sh](build-v1.3-test.sh) from an explicitly pinned develop commit, using the commands supplied with this checkpoint. The script calls the existing build-release.sh in a clean temporary detached worktree, bundles production dependencies, checks the archive and writes a SHA-256 sidecar. It leaves the working branch/files and the official v1.2 ZIP unchanged. PHP, Composer, Git, zip, unzip, Python 3 and sha256sum must be available on the build computer.

Use a test WordPress site and take a database/files backup first. In Plugins → Add New → Upload Plugin, select the test ZIP and replace the installed copy of this plugin when prompted. Keep the same plugin directory/slug; do not install a second renamed copy. Visit the Swim Training administration pages as an administrator so the additive schema upgrade can run. Existing workout/history data must remain available. Replacing the PHP files alone does not reverse a database upgrade or imported data; restoring the test-site backup is the rollback path.

The test package is not a GitHub release or WordPress.org deployment. Its version remains 1.3-dev. Its checksum is specific to that locally built file and must not be substituted for the official v1.2 checksum.

## Connect and choose supported data

Open the existing Garmin Connect page under Swim Training while signed in as the swimmer who owns the records. Save/test that swimmer's Garmin Personal API key using the existing connection controls. Keys stay in the plugin's encrypted per-user storage; do not include keys, tokens or raw health responses in testing reports.

| Category | Current import support |
| --- | --- |
| Pool swims | Recorded swimming FIT activities through the existing importer/matching rules |
| Open-water swims | Recorded activities; unmatched locations or ambiguous matches require existing review controls |
| Weight | Individual readings in verified kilograms, including multiple readings per day |
| Body composition | BMI only |
| SpO2 | Garmin provider summaries, with daily/window, sleep and seven-day baseline roles kept separate |
| Blood pressure, other activities, other composition fields, individual/hourly SpO2 | Not currently imported |

Garmin may not expose every old record for an account, even if a date range is accepted. Empty responses mean Garmin returned no data for that query. They do not establish that no historical data ever existed. Unsupported fields are excluded rather than assigned guessed units, zeros or averages.

## Manual and regular automatic measurements

The Private measurements section imports up to seven inclusive days with explicit category checkboxes. Results distinguish readings, daily category records, exclusions and failures. A repeated range skips exact duplicate observations; equal readings at different timestamps remain distinct.

Automatic private measurement imports are separate from activity synchronization and are off by default. Select measurement categories and save to enable the hourly rolling seven-day check. Clear all choices and save to disable it; existing records stay. Scheduled tasks depend on WordPress traffic. Saving a historical job does not enable either regular activity or measurement synchronization.

## Start a historical import

1. Open Import historical Garmin data on the Garmin Connect page.
2. Enter inclusive start and end dates, ending no later than today. For a full 2018 scan enter 2018-01-01 and 2018-12-31.
3. Select supported categories and choose Start historical import.
4. Review progress/results below the form. You may close the page or sign out; background work remains saved.

One unfinished job is allowed per swimmer. Its dates/categories are fixed. Resume it or cancel it before starting a different range. A completed/cancelled range can be scanned again safely.

Work runs in short background tasks, normally no sooner than one minute apart, with additional rate-limit/retry waits. Long ranges can take hours or longer, particularly on low-traffic sites. WordPress cron needs site traffic or an existing server cron setup to trigger tasks. Activity discovery includes every raw page before filtering for swims; there is no first-100-results cutoff. Activity totals are discovered progressively, so no invented total/percentage is shown.

## Controls and recovery

| Control/status | Meaning |
| --- | --- |
| Pause | Stop starting new work at a safe boundary; preserve progress |
| Resume / repair schedule | Continue a paused/blocked job or restore a missing scheduled task |
| Cancel — keep imported records | Terminal cancellation; already imported records remain |
| Retry failed items | Available after completion with errors; retry unresolved failures without approving review items |
| Waiting before retry | A saved backoff/rate-limit wait; automatic attempts are bounded |
| Blocked | Check the displayed reason, Garmin key/permissions or scheduling, then resume |
| Completed | Discovery/import work finished; review/exclusion counts can still require attention |
| Completed with errors | Some discovery or import work remains unresolved; the scan is incomplete |
| Cancelled | No further work will run for that job; a new scan requires a new job |

An operation already in progress may finish after Pause or Cancel. Imported data is not rolled back by job controls. Deactivating the plugin stops historical tasks; jobs require explicit resume after reactivation. Lost permissions or a missing key block work without deleting progress.

Progress refreshes while a job is active. Refresh pauses while controls have focus or the tab is hidden. Refresh job status is always available. If no task is scheduled, use Resume / repair schedule. A lost connection/browser session does not discard the queue.

Automatic retries are bounded to three attempts per work item and respect Garmin waiting periods. Failed activity discovery pages retain their cursor for retry; later dates can still proceed, but completion will explicitly report errors. Successful measurement categories are preserved while failed categories retry.

## Read results and review items

- Swims imported and swims already present count distinct activity outcomes.
- Readings added/updated/skipped count individual observations.
- Daily category records include import bookkeeping for weight/BMI as well as SpO2 summaries; they are not extra individual readings.
- Empty date/category responses and unsupported fields/rows are shown separately.
- All results, Failed items and Needs review filters show twenty work items per page. Recent historical jobs lists the ten most recent jobs; existing saved job links remain owner-only.
- Review Garmin activity / assign location opens the existing Garmin activity controls. Review pending import opens the existing pending-import screen. Review requires explicit approval/selection there.
- Review counts record the scan's outcomes. Completing review on another screen does not rewrite that historical job's result ledger.
- If an import committed just before a process interruption, replay can classify it as already present/skipped. Counts reflect the final durable outcome; the same observation/workout is not created again.

Activity duplicates use owner-scoped Garmin identities and verified file fingerprints plus existing conservative matching. A failed record is not treated as successfully imported merely because its Garmin ID exists. A changed source or incomplete association can require explicit repair. Measurement summaries can be refreshed when identifiable; conflicting same-time observations without a stable identity are preserved/flagged rather than guessed to be corrections. No existing records are deleted because a source request is empty or fails.

Jobs, controls, status and health data are scoped to the signed-in owner. Manage-all permission does not grant another swimmer's health-job access. These jobs are not exposed in public sharing or the existing external data-portability responses.

## Calendar and mobile display

Workouts/plans/events appear before measurements. Each date has one indicator per available measurement category. A compact day with insufficient room shows an ellipsis; tap/click the day or ellipsis to open its complete scrollable list. Measurement details retain all distinct readings, units and source/time evidence.

SpO2 provider averages, sleep summaries and seven-day baseline remain labelled separately. The plugin does not average unverified raw readings or combine summaries into a new daily average. Garmin's source calendar date controls placement; changing the site timezone does not move previously imported provider-dated measurements. Desktop, Android-sized touch Chromium and iPhone-sized touch WebKit are covered by automated tests; test your actual devices too.

## Sleep periods in expanded calendar days

Open a calendar day to see Sleep period, Garmin-local bedtime and wake time where stored SpO2 reports contain valid sleep boundaries. The duration is elapsed time between UTC boundaries, so daylight-saving clock changes do not add or remove an hour incorrectly. It is not measured time asleep and may include time awake; no sleep quality, stages or recovery claims are made.

The period is shown on its Garmin-local wake-up date. Identical UTC intervals repeated as sleep/next-sleep in adjacent reports display once; distinct intervals are shown separately and not added into an invented daily total. The latest fetched context supplies duplicate interval metadata. Single-day lookups inspect up to two neighboring report dates on either side within the existing owner-only, bounded endpoint. Numeric summaries retain their original provider dates.

Missing/invalid UTC boundaries, missing valid local wake time, nonpositive intervals, durations over 36 hours, or local/UTC boundary differences exceeding 14 hours do not produce a duration. The day details show an unavailable message when a SpO2 summary exists but no valid period is attributable to that day. Missing local bedtime displays Unavailable. No site timezone is substituted for unknown source-local time.

This uses already stored context, requires no Garmin calls or database migration, and works in the existing desktop/mobile expanded-day dialog. Refresh the calendar after installing; no reimport is required if the sleep boundaries are already stored. Summary-only SpO2 headings now say Garmin summary instead of 0 imported readings.



### Running and walking

Supported running and walking FIT activities can be imported manually or selected in Garmin discovery and historical imports. Scheduled land syncing is optional; existing swimming sync choices stay unchanged. The private workout log and calendar label each sport. Swimming totals include pool/open-water swimming only, with separate running and walking distance totals. Outdoor activities show the recorded route in their private detail page when usable GPS points exist; indoor/unknown activities do not invent routes. No running/walking coaching, personal bests or swim evaluations are generated. Cycling is not yet supported. Real-device acceptance remains pending and v1.3 is not released.


## Garmin page organization and connection setup

The owner Garmin page is ordered: Import Activities, Import Measurements, Automatic Sync, Historical Imports, Connection Settings. Until the current saved key passes the explicit Test Connection action, only Connection Settings is shown and it is expanded. Existing saved keys require this one-time test too; prior successful imports do not silently substitute for the test. After success the other sections are available and Connection Settings collapses. Section links support direct keyboard/touch navigation.

Replacing or removing a key clears its tested state. A failed explicit retest also clears it. Test state is private owner metadata tied to the current encrypted key; no token or plaintext credential is retained in that marker or returned to the page. Direct activity/detail/download requests and measurement/schedule controls cannot bypass the page setup gate. Nonces, ownership and existing capability checks still apply.

Automatic Sync groups activity and measurement controls without combining their preferences or schedules. This presentation gate does not switch existing background schedules on or off, cancel historical jobs or alter already imported records. Changing settings remains an explicit action. An existing due background task continues under its existing credential, permission, retry and scheduling checks; the page gate does not change its interval. The server's five-minute due-event runner does not turn hourly synchronization into five-minute synchronization.

Garmin-only panel, typography, checkbox and table styling is scoped to this page. Activity results no longer hide the other sections. Import result tables scroll within their own area on narrow screens. Historical activity counters use Activities rather than Swims because running and walking are supported. Runtime stays 1.3-dev and database schema stays 1.4; no schema migration or release/package action is part of this cleanup.
