# Optional scheduled Garmin measurements

Off by default, independent of activity synchronization. On the existing Garmin page, the current owner saves weight, BMI-only composition and/or provider SpO2 summary categories using a dedicated nonce. Clearing all choices cancels both hourly and continuation tasks without deleting measurements. No BP, uncertain composition units or raw/hourly SpO2 parsing is enabled.

WordPress cron starts an hourly rolling window covering today and the previous six site-calendar dates. Source calendarDate still determines stored placement; site dates select API requests only. Recent-first one-day batches share the weight response for weight/BMI. Each batch uses the existing bounded importer, transaction/duplicate rules and API cooldown. Single continuations walk every day so slow imports cannot starve older dates. One connection-level owner/site lock prevents concurrent workers consuming the cursor. Failed days retry at 5/10/20-minute delays, at most three attempts per window, with longer Garmin Retry-After honored (up to the existing 24-hour bound). Subsequent hourly windows revisit late uploads and provider report corrections. Samples without stable source IDs retain the existing conservative same-instant conflict behavior; the scheduler does not guess replacements or delete source-missing records.

The private job callback accepts only integer owners during WordPress cron, rechecks opt-in, the owner's capability and configured key, establishes that owner's WordPress context and restores the previous identity in finally. Existing API, storage and calendar authorization checks are unchanged. No new public route exists. Revoked capability, deleted owner or missing key cancels pending tasks; a missing-key user must save the schedule after configuring a key. Settings changed during a running request prevent that job from restoring its old continuation/state; already-started imports may complete. Plugin deactivation removes both types of measurement task.

Owner-only status on the Garmin page shows next UTC task, last attempt, job status and per-day/category counts. Stored job summaries contain statuses/counts only, never health values, raw responses or credentials. Failed/partial results remain visible and manual import remains available. Cron depends on site traffic; the UI detects absent hourly tasks and offers resaving the existing settings. Historical imports outside the seven-day window remain manual. No schema or release version changes.

Synthetic real-WordPress integration tests cover opt-in/off, actual cron callback, identity restoration, date overlap, duplicates/report correction, failure retry/cooldown, capability/missing-key denial, category changes, settings nonce and cleanup. PHP matrix and strict production-staging diagnostics remain required.
